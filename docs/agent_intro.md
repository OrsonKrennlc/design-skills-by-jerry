# Agent 使用入门

Agent（智能体）能调用工具完成任务。你告诉它目标，它会阅读材料、执行操作，再根据结果决定下一步；遇到不清楚的地方，也可以向你提问。[Anthropic 对 Agent 的介绍](https://www.anthropic.com/research/building-effective-agents)采用了这样的定义。

做设计时，可以让它根据需求写交互说明。连接 Figma 后，还能读取页面、制作原型，或检查页面与文档是否一致。具体能完成什么，要看模型、材料、工具和你给的权限。

## 1. Agent 是怎样做事的

假设你交给它一个任务：根据产品需求文档（PRD），为后台的“创建记录”页面补齐交互说明。

工具齐全时，它可能按这些步骤处理：

1. 读取 PRD，确认字段和业务规则。
2. 打开你指定的 Figma 节点，查看当前页面。
3. 参考已定稿的说明，整理字段校验、保存和取消等行为。
4. 将说明写入指定画布，检查是否有遗漏或文字裁切。
5. 返回交付链接，并说明哪些规则仍需你决定。

Figma 连接只支持读取时，它只能先交付草稿。遇到影响结果的业务规则缺失，也需要列出具体问题，等你确认。

不同产品都可能叫 Agent，但工作方式不一定相同：有的执行预设流程，有的让模型自行安排步骤。选用时，看看它能做哪些操作、会不会检查结果，以及什么时候需要你确认。

## 2. Agent 和大模型是什么关系

大语言模型通常缩写为 LLM，负责理解输入、处理材料和生成内容。如果系统支持工具调用，模型还会决定调用哪个工具、传入什么参数。应用执行这些操作后，再把结果交给模型。

Agent 通常包括以下部分：

| 部分 | 负责什么 | 设计工作中的例子 |
| --- | --- | --- |
| 大模型 | 理解需求、分析材料、生成内容、选择下一步 | 从 PRD 中提取字段规则 |
| 上下文 | 提供本次任务可用的信息 | 对话、PRD、页面截图、工具返回的节点信息 |
| 工具 | 读取信息或执行操作 | 搜索网页、编辑文件、读写 Figma |
| 执行与权限控制 | 安排工具调用，限制访问范围，处理确认和停止 | 允许读取样例，只允许修改目标分区（Section） |

同一个模型用在不同应用中，能调用的工具和权限可能不同，结果也会有差别。[Anthropic 对 Agent 组成的说明](https://www.anthropic.com/research/trustworthy-agents)介绍了模型、工具、运行环境与控制机制之间的关系。

普通问答通常回答后就结束，Agent 还可以继续调用工具，创建文件、页面或修改系统内容。聊天界面也可能支持这些操作，外观并不能说明它的能力。

## 3. Agent 能干什么

有现成材料、能说清要求、能检查结果的任务，比较适合交给 Agent：

| 任务 | 可以交给它的工作 | 你需要检查的地方 |
| --- | --- | --- |
| 整理资料 | 阅读文档、归纳需求、对比版本差异 | 有没有遗漏条件，引用是否准确 |
| 写作 | 起草交互说明、改写文案、统一术语 | 业务规则和语气是否符合项目要求 |
| 设计 | 读取页面、复用组件、生成状态画面或原型 | 布局、组件用法和操作路径是否合理 |
| 数据处理 | 合并表格、清理重复项、计算指标、制作图表 | 数据口径、公式和异常记录是否正确 |
| 文件与开发 | 批量整理文件、生成网页、修改代码、运行检查 | 改动范围是否准确，产物能否正常使用 |

分析一张上传的截图，只需要把图片发给它。要直接修改对应的 Figma 文件，就需要连接可写的工具，并授予文件访问权限。读取其他外部资料也需要相应工具。

可以先让它整理材料、起草说明，再检查结果。产品方向、尚未确定的业务规则和需要对外负责的决定，仍由负责人确认。例如，Agent 可以比较两种取消流程的影响，最终采用哪种由产品负责人决定。

如果只是改顺一句话，直接问就可以，不必接工具或搭自动流程。

## 5. 先分清几个常见名词

### Prompt：这次要它做什么

Prompt 就是你发给 AI 的指令，也叫提示词。它可以很短，例如“把这段说明改得更容易读”，也可以包含任务范围、参考材料和验收要求。

直接用日常语言交代任务就可以，不需要先学编程。把页面链接和业务规则给准确，通常比琢磨提示词句式更管用。

### Skill：一套可以重复使用的做法

Skill 把一类任务的做法写进文件，也可能带有模板、参考资料或脚本。Agent 做相关任务时会读取这些内容。例如，本仓库的 `web-interaction-spec` 规定了怎样根据需求和页面整理 Web 交互说明。[Agent Skills 官方说明](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)介绍了这种组织方式。

安装 Skill 通常不会重新训练模型，只是增加了一份 Agent 能读取的做法和材料，执行时仍可能出错。是否支持安装、怎样调用，要看应用自己的说明。

### 工具、连接器和 MCP：让它能访问外部内容

工具提供具体能力，例如读取某个文件、查询设计节点或创建页面。连接器负责接入某项服务。MCP（Model Context Protocol）是一种让 AI 应用与外部服务交换信息、提供工具的协议；MCP 服务可以在本机或远程运行。具体提供哪些能力，由服务本身决定。[MCP 架构说明](https://modelcontextprotocol.io/docs/learn/architecture)对此有更完整的介绍。

本仓库的 Skill 说明怎样写交互文档、设计页面。要读写 Figma，还得另外连接相应工具并授权；只装 Skill 不会获得 Figma 权限。

### 插件：需要看里面装了什么

不同平台对插件的定义有所不同。一个插件可能打包 Skill、工具或连接器，也可能同时包含几种内容。安装前看清它提供什么、连接什么服务、申请什么权限。

## 6. 怎样交代任务，才能得到可用的结果

交代任务时，说清要做什么、参考哪些材料、允许改哪里，以及最后要拿到什么。设计任务尤其要分清参考页面和可修改页面。

“帮我看看这个页面”可能得到一段泛泛的建议。如果你要的是交互说明，可以直接这样写：

```text
使用 web-interaction-spec，为后台“创建记录”页面补齐交互说明。

需求依据：附件中的 PRD，以已确认的业务规则为准。
当前页面：[粘贴目标节点链接]
定稿样例：[粘贴说明板链接]，只读参考。

只允许在目标 Section 旁新建 Interaction 说明板，不修改原 UI。
沿用样例的语言和结构，覆盖字段校验、保存、取消及错误反馈。
PRD 没有确定的业务规则，请集中列出问题，不自行补成既定规则。
完成后给我说明板链接，说明检查过哪些状态。
如果无法写入 Figma，先交付正文，并说明未完成的写回步骤。
```

示例里的链接需要替换成实际地址。若任务只需要草稿，把交付方式改成“只交付正文”即可。

修改时直接说期望的行为，例如“取消后回到列表，并保留筛选条件”，比“这里体验不好”更容易改对。业务规则变了，也要指出哪条旧规则已经作废。

## 7. 给权限时，要看哪些内容

按任务需要给权限：整理一份文档，就先提供那份文档；修改一个页面，就指定这个页面。需要访问更多材料或修改更大范围时，再让它说明原因。

提示词中可以写“只改这个文件”，同时也要看应用或服务的权限设置。文件夹限制、只读权限和网络限制，能实际约束它的操作范围。[Anthropic 关于 Agent 隔离与权限控制的说明](https://www.anthropic.com/research/how-we-contain-claude)解释了这类边界的作用。

### 常见权限意味着什么

| 权限 | 需要留意什么 | 入门时可以怎样设置 |
| --- | --- | --- |
| 读取文件或云端资料 | 可能接触客户资料、内部文档和个人信息 | 只提供本次需要的文件或文件夹 |
| 写入、移动或删除文件 | 可能覆盖内容、打乱目录或批量删除 | 在副本中操作，限定输出目录，保留版本或备份 |
| 访问账号和业务系统 | 可能以你的身份读取或修改共享内容 | 核对登录账号、工作区和读写范围，优先使用受限账号 |
| 浏览器或屏幕操作 | 可能看到已登录页面和屏幕中的敏感信息，也可能点击提交 | 使用专门窗口或独立浏览器配置，只打开任务所需页面 |
| 终端、脚本或安装软件 | 可以批量处理数据，也可能运行下载的程序、修改设置或向外发送数据 | 要求说明用途和影响范围，在受限工作目录中运行 |
| 管理员权限或完整磁盘访问 | 可接触的系统资源和可修改范围显著增加 | 先确认为什么当前任务确实需要，再决定是否授予 |

只读权限仍可能让 Agent 看到隐私内容。桌面应用也可能把本地读取的材料发给云端模型。处理公司资料前，先确认公司允许使用的服务，再检查数据保留、训练用途和第三方共享设置。

### 出现授权弹窗时

核对它准备做什么、操作哪个对象，以及权限会持续多久。比如“访问文件夹”，要看是当前项目还是整个文档目录；“连接账号”，要看是否包含发送、删除或管理成员的能力。

“仅本次允许”“本次会话允许”和“始终允许”的作用范围可能不同，以应用显示的说明为准。初次使用时，优先选择范围较小的授权。看不懂某项操作，可以让 Agent 用日常语言说明它会读取、修改或发送什么，以及能否撤销，再决定是否继续。

范围已经确认、操作可撤销且风险较低时，可以让它连续完成。例如，允许它在指定副本中整理格式，不必每改一段都确认。发送邮件、公开分享、付款、删除重要内容、修改线上系统等操作，则适合单独设定确认点。确认前应能看到实际收件人、最终内容或具体改动。

### 凭据和任务结束后的处理

优先使用平台提供的登录授权流程。需要 API Key（程序访问服务的密钥）时，使用平台的密钥管理或受保护的配置方式，并限制用途和有效期。避免把密码、验证码或完整密钥粘进聊天、文档和截图。

任务结束后，撤销不再需要的账号连接或临时权限。撤销权限会限制后续访问，已经发送的内容、公开的链接和完成的修改仍需要分别处理。若密钥已经泄露，应到对应服务中撤销或更换。

## 8. 留意外部材料中的可疑指令

Agent 会读到网页、邮件、文档和工具返回的信息，其中可能夹带诱导它改变任务的指令。这类问题叫提示词注入。例如，你让它总结一个网页，网页里却要求它读取其他文件并上传到某个地址。这条要求来自网页作者，超出了你的原始任务。[OpenAI 对提示词注入的说明](https://openai.com/safety/prompt-injections/)介绍了这种风险。

使用时可以留意这些情况：

- 为完成一个普通任务，突然要求读取无关的私人文件或输入密码。
- 网页或下载的材料要求关闭安全设置、扩大权限，或上传整个项目。
- 安装 Skill、插件或连接器时，申请的权限明显超过它描述的用途。
- Agent 准备向陌生地址发送数据，却无法说明与当前任务的关系。

遇到这些情况，先停下相关操作，检查材料来自哪里、数据要发给谁。即使用的是可信工具，也要留意它读到的外部内容。提示词要求和实际权限限制需要配合使用。

## 9. 使用过程中，还需要知道什么

### 它可能把错误说得很确定

Agent 可能编造引用、误读页面、算错数字，也可能把工具失败误报成任务完成。涉及业务规则、数字或引用时，请对照原始材料核对，不能只看回答是否流畅。

需要最新信息时，要求它实际查询并给出来源。搜索得到的内容也要判断日期和适用范围，模型凭记忆回答不能证明信息仍然有效。

### 上下文和记忆都有范围

上下文是模型本次处理任务时能看到的信息。对话变长后，早期内容可能被压缩、遗漏，或没有被准确使用。把定稿规则和重要决定保存在独立文件中，并在需要时让 Agent 重新读取，比依赖长对话更方便核对。[关于 Agent 上下文的说明](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)讨论了这些限制。

有些产品还提供跨对话记忆，需要查看它保存了什么、在哪些任务中生效，以及怎样修改或删除。上传文件、添加 Skill 和保存记忆，通常不会直接改变底层模型的参数。

### 多步骤任务会消耗时间和额度

一次请求可能触发多轮模型调用，以及搜索、文件处理或其他服务。消耗取决于实际执行过程。可以提前设定时间或费用上限，让它在反复失败、需要购买服务或准备扩大任务范围时停下来说明原因。

有些平台用 token 统计模型处理量。Token 是模型拆分和处理文本等内容的单位，不能简单等同于一个汉字或一个英文单词。具体额度和计费方式以所用服务的说明为准。

### 持续运行需要产品支持

关闭应用后能否继续工作，要看产品是否支持后台运行。定时任务和完成通知也需要相应功能与配置。安排长期任务前，确认运行条件、权限、费用上限和停止方式。

## 10. 怎样检查它是否完成了任务

拿到结果后，打开文件或页面，对照开始时的要求检查：

- 链接是否指向正确的文件、页面和版本。
- 是否覆盖指定状态，有没有把建议写成已经确定的业务规则。
- Figma 中的文字是否可编辑，是否存在裁切或重叠。
- 要求可点击原型时，主要路径是否实际走得通。
- 是否误改了范围之外的页面，或覆盖了原有内容。

只生成正文时，还需要完成画布写入；使用模拟数据的演示，还要在真实业务系统中验证。让 Agent 分别说明已经完成的工作、做过的检查和剩余限制。

发现结果偏离目标时，先指出具体位置和期望行为。如果出现误删、错误发送或越界修改，先停止继续执行，保留操作记录，检查版本历史或备份，再处理恢复和权限撤销。已经对外发送的信息通常无法靠本地撤销收回。

## 11. 第一次使用，可以从一个小任务开始

准备一份不含敏感信息的需求、一个页面副本和一份定稿样例。先让 Agent 读取材料，生成一小段交互说明；确认它理解了业务规则，再允许它写入指定位置。检查通过后，再把范围扩大到相邻状态或完整流程。

接下来可以按[安装教程](platforms.md)让 Agent 装好全部技能，再按任务调用。读写设计文件前，先完成[Figma 连接教程](figma.md)中的设置。任务示例见[使用方法与提示词](usage.md)。
