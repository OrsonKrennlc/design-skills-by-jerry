# Agent 使用入门

这篇文档面向零代码基础的 UI / UX 设计师，介绍如何在不写代码的前提下，配合本仓库的设计技能（Skills）和 Figma 连接工具，让 Agent 辅助完成 UX 设计与说明工作。

## 1. Agent 能做什么

平时用 AI 聊天，你问一句、它答一句，最后还得自己把文字一条条复制到 Figma 里。Agent 可以看作一个能读需求文档、看懂设计稿，还能直接动手建画板的助理。你交代好目标和范围后，它会自己拆解步骤、调用工具读取资料或操作画布，遇到拿不准的业务规则再停下来向你确认（参考 [Anthropic 对 Agent 的介绍](https://www.anthropic.com/research/building-effective-agents)）。

配合本仓库的 UX 技能，Agent 在 Figma 工作流中主要分担三类工作：

| 仓库技能 | 对应设计阶段 | Agent 可以做什么 | 仍需你决定的事 |
| --- | --- | --- | --- |
| [web-prototype-design](../skills/web-prototype-design/SKILL.md) | Web 端原型设计 | 通读 PRD 做全局 UX 规划，按设计系统制作可编辑的 Figma 页面、关键状态与任务流程 | 信息架构取舍、视觉风格、组件库之外的特殊样式 |
| [web-interaction-spec](../skills/web-interaction-spec/SKILL.md) | Web 端说明与审查 | 根据 PRD 与页面节点编写 `Interaction` 交互说明板；对照 PRD 检查已有原型是否一致 | 未定稿的业务规则、异常分支兜底策略、评审结论 |
| [tvos-interaction-spec](../skills/tvos-interaction-spec/SKILL.md) | TV 端交互说明 | 编写或审查电视页面交互说明，逐状态补齐 `Screen Design / Entry Point / Interaction / Controls` 及遥控器六键与返回焦点 | 遥控器焦点流转偏好、跨页面返回策略、真机体验验收 |

重复性的拆需求、补状态、写说明和查漏补缺可以交给 Agent；产品方向、视觉判断和需要对外负责的业务规则，仍由设计师和项目负责人决定。

## 2. 四个常见概念

使用 Agent 时经常会遇到下面四个词，用设计团队的日常协作来理解就行：

| 概念 | 类比 | 在 Figma 任务中的作用 | 常见误区 |
| --- | --- | --- | --- |
| Prompt（提示词） | 派活的需求单 | 用日常语言说明这次改哪个页面、参考哪份 PRD、写到哪里 | 以为要背固定句式或学编程；把页面链接和规则说准更管用 |
| Skill（技能） | 团队的规范手册 | 把一类任务的做法和格式写进文件，比如本仓库的三个 UX 技能规定了说明板怎么写、原型怎么规划（见 [Agent Skills 官方说明](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)） | 以为装了 Skill 就能直接改 Figma，其实 Skill 只管做法，不管连接 |
| MCP / 连接器 | 软件接口与权限 | 负责把 Agent 连到 Figma（见 [MCP 架构说明](https://modelcontextprotocol.io/docs/learn/architecture)），决定它能不能看图、能不能改画布 | 连上后才发现只有只读权限，或者没打开本地插件导致无法写入 |
| Context（上下文） | 桌面上的参考资料 | 本次对话里发给它的 PRD、定稿样例、Figma 节点链接和聊天记录 | 对话太长后早期规矩容易被遗忘，导致后半段输出走样 |

Skill（教它怎么做）和 Figma 连接（给它操作权限）是两件事。只装本仓库的 Skill 而不连接 Figma 时，Agent 依然可以读你上传的 PRD 附件和截图，输出可复制的文字草稿；只有连上可写的 Figma 工具后，它才能直接把内容写进画布。

## 3. 选工具和连 Figma

### 选哪类客户端

按自己的工作习惯选即可。如果习惯在聊天界面里读 PRD、做全局 UX 规划、写交互说明正文或出审查报告，可以先用 ChatGPT 桌面端、Claude 或 WorkBuddy。如果需要配合本地 Figma 插件连续读写画布，或者做完设计顺手生成可预览的网页，可以选 Cursor、TRAE、Antigravity 或 Claude Code。具体安装方法见[安装教程](platforms.md)。

### Figma 连接的两种模式

配置连接前，先看清你这次需要哪种权限，详细步骤见 [Figma 连接教程](figma.md)：

- 只读模式：能看图、能出文字草稿，但不能改画布。适合做原型审查、整理交互说明正文，或者先让 `web-prototype-design` 输出规划清单，不用担心画板被改乱。
- 可写模式：能直接在画布建图层、写说明板。可以通过平台支持的官方连接（支持列表见 [Figma MCP 总览](https://help.figma.com/hc/en-us/articles/32132100833559-Guide-to-the-Figma-MCP-server)），或在本地运行 [Figwright](https://github.com/awdr74100/figwright) 插件来打通。

## 4. 怎么把任务交给 Agent

### 准备三样材料

1. 需求依据：Markdown（`.md`）格式或清晰的文本版 PRD；没有正式 PRD 时，整理一段明确的规则说明也可以。
2. 当前作业面：在 Figma 中选中目标页面或 Section，右键点击 **Copy link to selection** 获取精确节点链接，避免只给整个文件的首页链接。
3. 风格与格式参考：同项目里已定稿的说明板或规范页面链接。用 `tvos-interaction-spec` 或 `web-interaction-spec` 时，给一份定稿样例比用文字描述排版要求准确得多。

### 划清参考区和作业区

派活时要明确告诉 Agent 哪里只准看、哪里才能改。PRD、组件库、定稿样例和不想被动的原 UI 设计稿都划为只读参考区；另外新建的空白 Section、页面副本或指定的 `Interaction` 画板作为可写作业区。

### 用日常语言派活

说清调用哪个 Skill、依据什么材料、操作哪个节点、禁止改什么，以及要拿到什么结果就行。比如用 `web-interaction-spec` 补齐后台页面说明：

```text
使用 web-interaction-spec，为后台“创建记录”页面补齐交互说明。

需求依据：附件中的 PRD，以已确认的业务规则为准。
当前页面：[粘贴 Copy link to selection 得到的节点链接]，原 UI 保持只读。
定稿样例：[粘贴说明板链接]，只读参考其语言、结构和版式。

写入范围：只允许在目标 Section 旁新建 Interaction 说明板，不要修改原 UI。
未定规则：PRD 中没有写明的业务规则，请集中列成待确认问题，不要自行脑补成既定规则。
交付要求：完成后给我说明板链接，并列出检查过哪些状态；如果当前无法写入 Figma，先交付正文草稿。
```

电视端六键焦点梳理、Web 全局 UX 规划和原型对抗性审查的现成模板，可以在[使用方法与提示词](usage.md)里直接复制。

## 5. 安全和常见限制

### 画布防误改

第一次让 Agent 写入画布时，先在测试副本或新建的空白 Section 里试跑，确认版式和内容没问题再用到正式页面。软件弹出授权窗口时，留意它要操作什么对象、权限持续多久，初次使用优先选“仅本次允许”；看不懂的操作，先让它用日常语言解释清楚再确认。万一写错位置或误删内容，先让它停下来，直接用 Figma 的版本历史（Version History）回滚。

### 保密和账号边界

把未上线的 PRD 或内部设计稿发给云端 AI 前，先确认该工具和账号符合公司的数据安全要求。配置 Figma Token 或 API Key 时，只填进客户端指定的配置入口，不要把密钥、密码或验证码粘进聊天框或截图里。

### 它可能把猜的内容说得很确定

Agent 有时会把猜出来的规则写得很笃定，或者在工具执行不完整时依然汇报已完成。设计任务里最常遇到三种情况：自己脑补了 PRD 里没写的弹窗提示或报错文案；漏掉了空状态、加载中、无权限或长文本折行；往 Figma 写入文字后出现裁切、重叠或字体缺失，但它自己看不到实际渲染效果。把“未定规则集中列出、不要自行补充”写进要求里，并在完成后亲自看一眼画布，能省去很多返工。

### 对话太长会忘掉前面的规矩

同一个窗口聊太久后，Agent 可能会忘掉最开始定下的组件规范或只读限制。切换到新模块或新页面时，建议新开一个对话。用 `web-interaction-spec` 对上一轮做出的原型进行审查时，也建议新开对话并重新提供 PRD 和原型链接，避免它顺着上一轮的思路替自己圆场。

## 6. 检查结果和首次试用

### 拿到交付后的检查项

每次 Agent 汇报完成后，打开 Figma 核对这五项：

1. 返回的链接是否指向指定的 Section 或画板，范围之外的原 UI 有没有被误改。
2. 写入 Figma 的文字是否可编辑，有没有出现文本裁切、换行错乱或图层重叠。
3. 要求的状态是否覆盖完整（比如 TV 端的遥控器六键与返回焦点、Web 端的表单校验与报错），有没有把待定问题擅自写成既定规则。
4. 用 `web-prototype-design` 生成的页面是否正确复用了指定组件库，而不是手动拼出非组件化的矩形。
5. 如果因为权限问题只交付了正文草稿，确认自己是否已把正文整理回画布，或补齐了未完成的写回步骤。

### 第一次试用从小任务开始

找一份不含敏感信息的历史 PRD 和一个 Figma 页面副本。先不让它改画布，用 `web-interaction-spec` 或 `tvos-interaction-spec` 让它读取材料并输出一份文字版交互说明草稿，确认它理解了业务规则和样例格式。草稿没问题后，再打开可写连接，指定一个空白 Section 让它写回一两个状态的说明板，在 Figma 里检查过排版和文字后再扩大范围。

完成这些准备后，可以按[安装教程](platforms.md)装好技能包，再按[Figma 连接教程](figma.md)完成连接设置。
