# 使用方法与提示词

## 开始前

确认当前 Agent 能读取你提供的材料，并已安装本次任务需要的技能。需要实际读写 Figma 时，再按[连接教程](figma.md)配置工具；只交付正文时可以直接使用附件材料。第一次使用 Agent，可以先读[使用入门](agent_intro.md)。

## 给 AI 什么材料

| 材料 | 用途 |
| --- | --- |
| 本次需求 / PRD / 已确认规则 | 确定用户任务和业务行为 |
| 当前 Figma 节点链接 | 定位 Page、版本、画面和状态；在 Figma 中用 Copy link to selection |
| 一份当前项目的定稿样例 | 沿用术语、语言、粒度和说明板样式 |
| 任务范围 | 哪些页面可写，哪些只是学习来源 |
| 交付方式 | 正文、Figma 说明板、页面评审或可点击演示 |

没有 PRD 时提供现有需求即可；不要为了使用技能补造一份。只提供学习链接不代表允许修改那个文件。需要英文说明板时直接说明，中文聊天不会自动要求翻译 UI。

## 电视交互说明

先安装 `tvos-interaction-spec`，按需要连接 Figma。

```text
使用 tvos-interaction-spec。
产品是电视 OS，使用遥控器六键。
目标：[当前状态画面的节点链接]
样例：[同版本已定稿说明板链接]
范围：设置页主状态，以及打开/关闭确认弹窗的状态。
请在当前 Section 的画面旁写入 Documentation / interaction。
沿用样例语言和版式；每个状态写齐 Screen Design、Entry Point、
Interaction 与 Controls。Controls 按各张图的实际焦点写。
业务规则见附件；确实缺失的行为集中列出，不改原 UI。
```

只要一行一页大纲时：

```text
使用 tvos-interaction-spec，把我提供的电视首页规则整理为行级交互大纲。
每行概括状态序列、入口、上下映射、左右边界、OK 和 BACK。
此轮只交付可复制正文，不在 Figma 建板。
```

重点检查：获焦和选中是否区分；六键是否对应当前焦点；入口、取消、保存和返回焦点是否互相一致。画面核对不等于电视端实测。

## Web 原型页面设计

先安装 `web-prototype-design`，连接可写的 Figma 工具。

```text
使用 web-prototype-design。
需求：为后台设计“创建记录”和“编辑记录”流程，业务字段见附件。
使用者：[填写角色]；主要任务：[填写任务]。
只读学习来源：[设计系统或现有页面链接]
可写目标：[目标文件 / Page / Section 链接]
先完成可编辑页面和关键状态，本轮不用连接演示。
请沿用目标项目的组件、变量、文字样式与画布组织，
覆盖确实影响任务的依赖字段、校验和取消状态。
缺少规则时区分设计建议与既有要求，不从案例继承业务数值。
```

需要可点击演示时，在已经有页面和状态的基础上追加：

```text
请把这次范围内的主要操作连成可点击原型，设置演示起点，
走完创建成功、校验失败后修正、取消退出三条已有路径。
使用模拟数据，报告哪些画面已完成、哪些连线已检查、哪些路径已实走。
```

明确“先做页面”可以让工作集中在页面表达；指定“可点击演示”才把连线、变量和实走纳入交付。真实输入或服务结果无法模拟时，要说明范围。

## Web 交互说明

先安装 `web-interaction-spec`。只用上传资料写正文时，可以暂不连接 Figma。

```text
使用 web-interaction-spec。
根据附件 PRD、当前 Figma 页面和已定稿样例，整理创建与编辑流程的交互说明。
目标：[节点链接]
样例：[说明板链接]
写入位置：当前页面旁的 Interaction 说明板。
结构沿用 Entry → Function & Interaction；按当前画面的区域和控件组织。
只写有依据的规则，不扩写 PRD 未提及的实现细节，不修改 UI。
只有会改变当前任务结果的真实冲突需要集中列出。
```

只读审查时：

```text
使用 web-interaction-spec，只读审查这些页面与已有说明是否一致。
指出具体的 PRD / UX 或 UX / UX 差异，以及受影响的状态。
不要将 PRD 未展开的内容列成开发问题清单，不修改画布。
```

重点检查：每个状态有直接入口；字段依赖与保存/取消相容；当前版本准确；精确文案有依据；已解决的标记已清理。

## 可选组合

如果同时安装了原型与 Web 说明两个技能，可以先用 `web-prototype-design` 完成页面并评审定稿，再用 `web-interaction-spec` 为同一版本补说明。也可以只选其中一项，不影响其独立使用。

组合时把页面修改和说明修改的范围分别说清楚。说明任务不会自动授权修改原 UI；读取样例也不会授权更改样例。

## 怎样判断本次任务完成

- **写作：** 覆盖指定页面和关键状态，有依据的规则完整，建议与未决项可分辨。
- **Figma：** 实际写入指定位置，文本可编辑、没有裁切重叠，附实际产物链接。
- **原型：** 只按实际完成程度报告页面、连线、演示；使用模拟行为时说清楚。
- **工具不可用：** 给出当前资料支持的草稿，明确哪些实时读取或写回没有完成。

若 AI 只给泛化建议，可以继续指定：按技能读取当前节点、对照样例，直接完成本次明确范围，并按实际交付层级报告结果。
