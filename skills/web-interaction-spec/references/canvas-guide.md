# 画布设置与 Figma 操作

## 先确认项目模板

先测量目标版本附近的 2–3 块说明板，核对画面配对、板尺寸、文字位置、字体与字号、底色、行高和标题层级。已有用户定稿优先于此参考值。读取真实文本样式，不从截图估算尺寸。

没有现成模板时，可使用以下演示起点；这些是排版建议，不是从当前目标文件读取的事实。已有模板时以实测值为准。

| 项目 | 示例起点 |
| --- | --- |
| 说明板名称 | `Interaction` |
| 初始尺寸 | 1140×1080，内容多时加高 |
| 配对 | UI 在左、说明在右，顶部对齐 |
| 层级 | Entry → Function & Interaction |
| 正文 | 自然换行、可编辑；字号以目标画布可读性为准 |
| 布局 | 固定内容宽度，高度随内容增长；按每行最高对象安排下一行 |

不要继承旧文件的绝对坐标、固定高度、字体名或配色。先确认项目模板，再使用实际边界计算空位。

## 新建与更新说明板

1. 列出目标说明和附近边界，识别实际空位。更新原板优先；缺少对应状态说明才新建。不要把新板默认堆在画布原点。
2. 复用同版本样例的层级和样式。普通文本、Frame、必要的 Section 足够，不为文档创建全套组件库、变量库或修改共享组件。
3. 新板保持 `Entry`、`Function & Interaction` 的清楚层级。块之间适当留空，字段或操作标题加粗，正文自然换行。使用真正的列表或结构化布局，不用一串空格和手工断行模拟对齐。
4. 新建的相关文字容器优先用自动布局，固定文本宽度、让高度随正文增长。只改已有说明时，保留其可用结构；不为单纯改字重构全部说明板。
5. 内容溢出时先删重复背景和空泛句，不能删有效规则。仍放不下就加高说明板，并按该行最高对象给下一行留空间；需要拆板时使用明确的页面/主题名称连接正文。
6. 继续保留 UI 原尺寸和位置，移动说明容器不能悄悄拖动或缩放源设计。需要重排其他用户资产而超出任务范围时，先选择空位放置或交付布局建议。

## 差异标记与后续评审

- 用户要求标红时，在对应说明板写清 `PRD / UX`、`UX / UX` 或文案差异及其依据；用文字区分含义一致的措辞差异和行为冲突。PRD 未写某实现细节，不自动成为红色问题。
- 汇总板只留简短结论、仍需处理的真实差异和用户明确保留的待办。审查任务还可记录有证据的需求遗漏、流程矛盾及影响结论的待验证项，按类别区分，不能混算为已证实问题。可用其他颜色区分待办，但颜色含义服从项目和用户要求；不要给每个未定义细节建立一项。
- 定稿后更新所有受影响的说明并撤下旧标记；结论有必要保留时改成普通规则，不在画布中连续追加每轮问题、建议和聊天记录。
- 用户重置弹窗后，先重读对应 Frame 的当前子节点和文字，再截图。新弹窗可能有新 ID，汇总板也可能已移到 Page 层级；不要按旧父容器或失效 ID 继续修改。
- 画面中的弹窗可能与背景 Frame 同级浮放。Frame 截图未包含弹窗时，检查相邻对象及其边界，分别截图核对；不能直接认定弹窗缺失。

## 文字与 API 细节

在使用 `use_figma` 时，先按当前环境要求加载 `figma-use`，以其当前 API 说明为准，不把历史代码当作工具保证。

- 使用异步方式切换到目标 Page；每次调用都重新明确页面上下文。
- 编辑已有文本前读取并加载它实际使用的全部字体。Inter 的样式名需确认，例如 `Semi Bold`，不能猜写为 `SemiBold`。中英混排须确认中文字体可用，不静默用缺字字体。
- 新长文本使用固定宽度与随内容增长的高度。设置好宽度再让正文自然换行；字号/行高与样例一致。源稿中的固定文本框和 `clipsContent=true` 不意味着允许裁掉新正文。
- 写入批次返回创建/修改的节点 ID 与尺寸等证据。失败可能部分执行时，先读画布再定向修复，不盲目重建产生重复板。
- 不因说明使用 instance 就修改 main component。确需转换为可编辑本地内容时，限于已授权说明实例；ID 变化后重新定位。
- 用户已授权同步修改 UX 时，只处理对应本地实例。切换控件变体后重读新子节点，核对禁用态、错误文案、提示文字和布局；属性写入成功不等于提示已显示，也不等于错误已从画面消失。

## 核验实际渲染

每块完成后核对：

- 文图配对和直接入口准确，弹窗/抽屉/hover 没有配到同名但不同状态的画面。
- 标题没有重复或粘连，正文无缺字、意外字重、残留占位文字。
- 文本完整显示，没有超出板边、被固定文本框截断或与其他块重叠。
- 画面与说明顶部对齐，长板没有侵占下一行；Section 边界能容纳新内容。
- 保存的是可编辑文字，而非只有截图的说明。

截图需足以看清文字；整页太大时分板检查。读取边界只能证明结构，不能代替实际渲染检查。只修复观察到的问题，修复后的通过截图即为本轮最终核验，无变化无需重复截图。
