# 从评审反馈提炼修订原则

本页是去标识的方法归纳，不包含实际项目链接、节点、账号或原始画布快照。

## 先重新读取，再解释修改

1. 读取用户当前的页面、可见文本、控件状态和合成截图。
2. 对照上一版已交付内容，确定哪些修改是当前定稿。
3. 用“改了什么 → 解决什么表达问题 → 可迁移原则”记录结论。
4. 区分项目约定和通用方法。用户删掉失败态或窄屏图，可能只是本轮范围缩小，不意味着以后永远不做。

## 常见修订与检查

| 观察到的修订 | 可迁移的检查方法 |
| --- | --- |
| 状态重新按列表、创建、编辑分行 | 用画布顺序表达任务，同一行从左向右呈现状态变化 |
| 增加前置选项未满足的中间状态 | 同时展示下游隐藏、禁用、可用三种语义中真正存在的分支 |
| 创建和编辑的标签、必填标记不同 | 分别核对两种模式，不直接复用整套字段配置 |
| 成功提示换了位置 | 沿用当前项目锚点；让提示和保存后的数据结果同时可见 |
| 放弃确认后面保留编辑表单 | 保持草稿上下文，不用列表底图替代正在编辑的现场 |
| 删除庞大的业务状态组件集 | 按当前评审需要组织页面，保留通用组件复用和人工修改能力 |

## 依赖字段的演示示例

以下为虚构方法示例，具体字段由本次需求确定：

- 未开启附加功能：隐藏相关设置。
- 已开启但未完成前置选择：显示相关设置，下游字段禁用，并解释前提。
- 前置选择完成：下游字段可用，已填值和格式符合当前规则。

只学习状态关系，不由此推导密码生成、邮件发放或服务端校验策略。

## 复核边界

- 弹层可能与背景同级，需检查合成画面。
- 残留节点名不代表业务用途；按可见内容与状态判断。
- 同一记录在前后状态中的代表数据保持一致。
- 用户只要求页面时，不把变量、热区或连线排错作为页面完成前提。
- 分别报告画面完成、连线检查、演示实走中实际完成的层级。
