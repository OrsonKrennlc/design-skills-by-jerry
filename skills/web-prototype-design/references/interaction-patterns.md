# 交互模式与验收

按当前任务读取相关模式。这里的“建议”用于填补新设计，不是对源文件的事实声明。只补能够帮助任务完成与恢复的状态，避免把每个小功能展开成完整组件百科。

## 页面和状态的最小约定

复杂流程可用下表压缩表达；简单操作直接写进原型说明即可。

| 页面/状态 | 入口与前提 | 操作 | 反馈与下一状态 | 返回及数据影响 |
|---|---|---|---|---|
| 新建任务 | 列表的主要操作 | 填写并提交 | 校验失败留在表单；成功回列表 | 明确新记录位置、原筛选是否保留 |
| 编辑任务 | 指定记录的 Edit | 修改并保存 | 提交中防重复；失败可重试 | 保留输入；成功显示新值 |
| 有未保存修改 | 关闭、取消或返回 | 继续编辑/放弃 | 根据当前规则关闭或恢复编辑 | 不把未保存值写入已确认数据 |

每行都应能对应原型画面及必要说明。新项目中的记录排序、筛选处理、校验时机、关闭行为等由需求或本次设计决策确定，不能照抄表内例子当成既有规则。

## 列表、搜索、筛选与分页

- 先定义用户如何识别记录与比较记录，再决定列。主标识可查看详情；状态有文字；行操作明确作用对象。用于识别的固定列与横向滚动区域不能互相遮挡。
- 搜索明确字段范围、提交触发及清空行为；筛选明确单/多选、即时生效或统一 Apply、重置方式。没有来源时，选择一种符合任务的方案并标记为建议，不能默认“自动模糊实时搜索”。
- 只在项目需要时设计排序、批量选择及跨页操作；明确影响范围和当前选中数。分页和筛选变化后的定位策略需要一致。
- 区分首次无数据、搜索无结果、加载中和加载失败。空态引导到可执行入口；无结果允许清空条件；失败保留条件并提供恢复入口。
- 长文本的截断与完整查看方式成对设计；关键内容不能只靠 hover 才能获取。表格在窄尺寸下优先保留关键列和操作可达性，必要时使用可发现的横向滚动。


验收关注：检索后能找到记录；清空后能恢复；无结果与错误有不同反馈；首末页按钮可用性正确；打开再返回不会无故丢失任务上下文。

## 表单与依赖

- 字段在需要时说明标签、必填性、输入类型、取值来源、默认值、长度/范围/精度、联动和错误文案。校验时机具体到提交、失焦或输入过程中；不要用“实时校验”概括所有字段。
- 按任务顺序分组。标签和输入区对齐；提示说明放在作出选择之前需要看到的位置；错误贴近字段，文字说明如何修复，不能仅用颜色或全局 toast。
- 上游选择变更时，重新评估下游已选值：仍有效就保留；无效时按本次规则清除或要求确认，并说明原因。隐藏字段的旧值是否保留、是否提交与是否校验要一致，避免界面隐藏但仍阻塞提交。
- 成对或重复字段按整体增加、定位和删除。部分填写的组如何处理由业务定义；不能因其中一项可选，就放任关联数据产生半组记录。
- 提交中避免重复提交；失败保留用户输入并说明重试路径。只有成功才将新值呈现为已保存。远程唯一性或权限检查不能由静态画面假装已完成。


验收关注：空值、边界值、重复值、上游更换、部分组、长错误、失败重试至少覆盖当前任务真正可能失败的情况。对新增项目，记录所选规则的理由即可，不必为每项制作一张独立画面。

## 抽屉、模态框与返回

- 抽屉适合在保留列表上下文时完成局部任务；字段过多时先考虑分组、章节导航或独立页面，不能只把抽屉越拉越宽。
- 头部提供标题与关闭入口；正文有明确滚动区域；操作区在长内容中可达。主次操作顺序一致，避免提交按钮随内容滚出视口后无处保存。
- 分别确定 ×、Cancel、遮罩点击、Escape、浏览器返回的行为。可以共用一个关闭策略，但必须说明有修改、未修改、提交中以及确认弹层出现时的差异。来源没有说明的行为以本次设计建议呈现。
- 确认放弃时明确丢弃的是本次草稿；继续编辑返回原输入位置。不要在没有数据丢失或重要后果时为每次关闭增加确认。
- 模态对话框的 Web 键盘建议：打开后焦点进入对话框，Tab 在内部循环，Escape 进入关闭流程，关闭后焦点回到触发处或合理的后续任务位置；背景不可操作。这些是 [W3C APG Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 的指导，不是此次 Figma 已有行为的证明。涉及放弃修改时，Escape 先进入该关闭策略，不绕过确认。


验收关注：按状态画面核对编辑、继续编辑、放弃修改和返回列表的关系；保存失败后可继续编辑；长内容不会遮挡错误或操作。浏览器焦点与返回行为列为交接要求。

## 重要后果与状态联动

- 先判断后果，再选确认方式。明确对象、影响范围及恢复方式；确认框不能只写“确定操作吗”。
- 保存、停用、删除、归档是不同动作；不根据样例中的词自行改变产品语义。禁用操作说明前提，提供去解决前提的路径；tooltip 只作补充。
- 状态切换依赖服务成功时，区分提交中、成功与失败；失败不能让列表永久显示未生效的新状态。成功后更新文字、可用操作和关联影响。


## 响应、可达性和原型真实性

- 用真实长度的示例检查多语言、长名称、计数和错误；图标按钮有可理解的名称与命中区域。状态不能仅依赖颜色；重要提示不应只能鼠标悬浮访问。
- 根据目标用户的使用尺寸验证侧栏、工具栏、表格与表单。窄尺寸变化要说明折叠、换行、滚动及操作入口的位置，而非只给另一张缩小截图。
- 通过组件现有变体和状态画面表达唯一性错误、提交失败及成功等设计结果；示例数据与业务规则保持一致，不声称已执行真实校验或提交。
- 核对图层结构、实际截图和静态状态关系，明确其与运行产品验证的区别。
- 当用户只需要验证一个局部操作时，交付能说明该操作的最小完整路径；当需求是完整任务，检查入口至结果及恢复出口，不以一张精美首页代替任务完成。
