# 从 Figma 建立当前任务的设计基线

本页是去标识的读取与组织方法，不包含作者的私人文件、节点或组件标识。每次设计先读取本次用户提供的来源，不能宣称已经学过未取得的文件。

## 选择有代表性的样本

先读浅层结构，确认 Page、版本、业务区、组件区和原型范围，再选列表、简单表单、依赖字段、弹层及反馈状态。来源仅用于学习时保持只读；写入到用户指定的新区域或目标文件。

查看实际合成截图。弹窗、蒙层和确认层可能是同级节点，不能只看背景 Frame 的 children。

## 提取角色与数值

| 角色 | 需要核对 |
| --- | --- |
| 页面外壳 | 侧栏、顶栏、导航状态、内容区、滚动与固定区域 |
| 排版 | 字体、字重、字号、行高、文本混合样式和长内容 |
| 色彩 | 语义角色、变量模式、别名、透明度与背景 |
| 间距 | 页面留白、组间距、标签/控件间隔和控件内边距 |
| 控件 | 高度、圆角、边框、图标、禁用/错误/选中状态 |
| 弹层 | 背景、遮罩、正文滚动、操作区和关闭路径 |
| 反馈 | 锚点、层级、与操作后数据结果的关系 |

记录“值 → 来源节点 → 角色 → 是否实测”。不能用截图估计值冒充节点实测，也不能将某一控件的间距推广为全文件网格。

## 组件复用

- 先确认实际实例来源、组件属性、变体名、变量与样式，再设置属性。
- 当前文件的节点 ID 不是跨文件导入 key。跨文件资产不可用时先说明，必要时按已提取规格重建当前任务需要的组件。
- 保留原变量绑定与别名；不要为相同语义创建平行色板。
- 用 Auto Layout 表达内容关系，正文自然换行、高度随内容增长。
- 保留通用控件；业务状态以易于评审和人工修改为准，不预先制造庞大组件矩阵。

## 用页面关系组织评审

同一任务从左向右排关键状态；列表、创建、编辑可以按任务分行。具体画面尺寸、编号、坐标和间距服从当前文件。通用组件样本放组件区；评审区保持主要路径清楚。

## 学方法，不继承业务规则

名称长度、分页条数、冻结列数、账号依赖、反馈时长、搜索策略及权限必须来自本次需求或明确的本次设计决策。示例数据和旧图层名不能证明产品行为。

读取不到来源时用已有材料推进，并区分设计建议与既有规范。分别报告页面完成情况和静态状态核对范围，不将其称为运行产品验证。
