# 电视页面交互文档

把设计画面写成可直接交付的简洁交互说明。状态文档以当前画面的焦点为单位；用户要求“一行一页交互大纲”时，概括该行的状态序列和边界，不为每张图重复建板。沿用用户亲自修改或确认的格式和文风。

## 交付约定

- 提供 Figma 链接并明确要求写回设计稿时，在同一 Page / section 中页面旁的 `Documentation / interaction` 画布完成。已有项目约定默认写回时沿用；未指定载体或只提供学习链接时，先交付可复制正文。明确要求只读审查、对话或本地文档时，按当次要求执行。
- 写入范围限于目标页及直接相关状态的交互说明。保留用户已改好的样例，不改源 UI 内容、原型行为、其他页面或共享组件定义。缺少写入权限或工具不可用时如实说明，不能把本地草稿说成已写回。
- 文档语言、术语、字体、颜色、图标、双列 Controls 和画布尺寸沿用邻近的用户定稿。对话使用中文，不代表画布里的英文说明要翻译成中文。
- 使用官方 MCP 的 `use_figma` 时，先加载官方 `figma-use`；使用 Figwright 时，改用其实际提供的读取、写入和截图工具，不假定存在同名官方工具或技能。未连接工具时完成已有依据支持的草稿，不声称已读取或写回 Figma。这里的说明板是普通可编辑画布图层；不为写文档擅自换成另一种文档产品。

## 确定对象与依据

- 首次写作或修改先读 [写作方法与例稿](references/writing-guide.md)。随附例稿为去标识的方法示例；具体项目的版本规则、历史原文和节点链接由使用者按任务提供，不从示例推断业务事实。
- **每次续写或修改都重新读取当前 Figma 对象。** 用户可能换图、移组、改文案或删建节点；历史 ID、名称和坐标只作定位线索。先识别 Page、版本 section、目标状态和对应说明，再核对当前画面与实际焦点。几何邻近不能独立证明配对；ID 失效时重新定位。
- 优先级按适用范围判断：用户最新明确指示 → 同版本用户定稿 → 该场景仍有效的旧规则 → 历史参考。保留旧规则已有的局部例外，不能用新的“全局”措辞覆盖未涉及的页面。当前画布与此前确认冲突且无法判断是否为用户新定稿时，指出具体位置并询问；不能把自己以前写的文案自动当成用户确认。
- 阅读组件实例内部文字、可见性、删除线、版本说明及可用原型事件。分小批提取所需内容，避免返回整页深层结构或完整组件属性。
- 区分产品与输入方式：WhaleTV / OS 10 不能自动套用 Apple tvOS 规则。原型的键盘演示事件不等于真实遥控器输入，转场时长不等于停留阈值；原型没有有效目标也不意味着画面和用户定稿已明确的行为都要标为建议。

## 状态与必备结构

按“焦点 + 可见内容 + 操作模式 + 时间阶段”区分状态。列表还要区分逻辑项目、屏幕槽位、滚动偏移和经过的轮次；同一个项目或第 1 槽位不一定代表初始状态。性别未选/已选、弹窗、回填后按钮获焦需要分别核对；同构选项无需各复制一整份说明。

每个状态的 `Documentation / interaction` 必须按以下顺序齐全，**弹窗也不能漏掉 Screen Design**。现有模板少了某节时补齐，不能把模板缺项当成省略依据。

| 层级 | 内容 |
| --- | --- |
| General Behaviour → Screen Design | 当前可见的布局、内容区域、控件及遮罩。说明“有什么、在哪里”，不放操作流程或核查记录。 |
| General Behaviour → Entry Point | 进入当前状态的操作/条件，以及具体的默认焦点。 |
| General Behaviour → Interaction | 当前状态的选择、反馈、内容联动和必要规则；区分获焦与选中，避免重复前两节。 |
| Controls | `UP / DOWN / LEFT / RIGHT / BACK / OK` 六键各自的单次操作结果。行级大纲可列必要条件分支；额外输入有依据且相关时再添加。 |

页面确实需要全局概览时补 Annotation；跨状态计时、保存/取消或复杂分支确有必要时再补流程，不为简单页面扩写 PRD。

## 写作口径

- **按当前截图的焦点写 Controls。** Male 获焦时写 `RIGHT → To Female option.`，不在这一格混写整页所有区域的右键规则。Year 获焦的弹窗写 `UP → Previous year.`、`RIGHT → To Month.`。跨字段通用机制放 Interaction，其他状态的局部操作放各自说明。
- 卡片左右邻项用 `last / next`，例如 `To last card.`、`To next card.`，不写样例广告名称；末项/首项循环与边界另写清楚，避免把 last 邻项与列表末项混淆。上下目标用“相邻行名称 + 该行第几项”，例如 `To Apps Row 1st item.`；序号须有画面或定稿依据，不能为统一句式编造。真实行名如 YouTube、Prime Video 可以保留。概览中的可变目标使用已确认的映射规则，不强行固定序号。
- 没有其他项目术语时，导航区域可称 `Navigation Bar`；已有定稿时沿用项目术语。更换措辞时保持原有行为和目标；何时打开导航、焦点落在 Home 还是头像，仍由当前场景决定。
- Entry Point 分行写来源操作与默认焦点，例如 `Press DOWN from Male.` 下一行 `Default Focus: Age.`；普通按键结果可写 `To Age.`、`Select Male.`、`Return to TOU agreement.`。短句应能定位目标；有条件分支才展开，不把简单行为写成多段审查意见。
- 用户定稿中用于边界/无动作的 `Null` 沿用其写法，不再扩写为“原文 Null，含义待确认”。单独来源里的空白、`/` 或未解释的 Null 仍不能当作已确认无动作；真正未知的行为也不能用 Null 掩盖。
- 优先采用用户当前定稿中的规则、术语和精简程度。对画面及项目已确认惯例可支持的常规焦点映射，直接写出结果，不因原型不完整逐项加 `[Proposed]` / `TBD`。
- 不把状态编号、节点 ID、图层命名诊断、隐藏 Hint 检查、版本冲突历史或“原型未验证”等核查备注塞进 Screen Design / Interaction / Controls。节点链接可用于定位或交付链接。
- 不凭空补业务分支、服务端结果、下游页面、默认日期、合法范围、长按或计时参数。真正影响实现的缺失/冲突在对话中集中简短说明；必要时只给受影响项留一个清楚的待确认标记，同时完成其余可确定内容。需要提出新方案时单独标为建议，不伪装成已有设计。
- 用户说“先留接口”的成功/失败反馈只记录触发点和待定呈现，不自创 Toast、弹窗、文案、时长或异常数据处理。并列方案保持并列，不能串成先后流程。询问时带具体画面、字段及冲突原文，避免追问已经回答过的内容。

## Figma 排版与更新

- 先读用户定稿的样例，再修改目标说明。优先在原画布更新；缺少说明的相关状态才新增，并与真实画面相邻。沿用现有文本样式、图标和自动布局。
- 用户指定“放在最左边”时按指定位置交付。先检查空间，确需让位时可在目标 section 内整体平移相关状态组，保留相对顺序和间距；不改 UI 内容，并检查 section 容纳及相邻组重叠。
- 批量改文案先确定版本、目标说明和具体字段，检查嵌套 section，预览命中数量后再写入。修改 BACK 不波及 LEFT 或 APP / 视频行例外；规则变更同时检查 Screen Design、Entry Point、Interaction 与相关入口说明，不能只替换 Controls。具体操作见写作方法中的“批量修改”。
- 若文档实例无法补段落，可仅将该说明实例转为可编辑画布再补齐；保留已有内容、位置和外观，不改共享组件。节点 ID 变化后重新定位并使用新链接。
- 一种可用的示例版式为 1280×1080、上方 General Behaviour、下方双列 Controls；尺寸和样式以当前项目定稿为准。优先精简正文以匹配定稿尺寸；必要规则仍放不下时扩展空间并避开邻近画面，不裁字或缩小到难读。

## 交付前逐板核对

- **每一块**都有 Screen Design、Entry Point、Interaction 和 Controls，顺序正确；尤其检查弹窗，不能只抽查主页面。
- 六键齐全，并与当前画面焦点对应；入口能走到当前状态，OK / BACK 的提交、取消和返回焦点互相一致。获焦不等于选中，移动焦点不擅自更改已选值。
- 用户修改过的样例保持原样；说明与同版本画面对应，隐藏或删除线内容未重新成为有效需求。
- 对本次范围检查旧术语、漏改字段与规则矛盾；左右邻项未写成样例广告名，上下目标的行名和序号与当前画面一致。批量修改汇总实际修改数与剩余命中，不向用户倾倒逐节点日志。
- 检查相关说明的实际渲染：字体、间距、尺寸、遮挡、文字溢出及相邻画布重叠。工具返回成功不等于排版已通过。
- 最终简短告知已写回的位置及必要的未决项。静态文档检查不宣称电视端实际交互已经测试。
